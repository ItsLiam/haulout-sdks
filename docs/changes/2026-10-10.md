# 2026-10-10: grouped bars and time windows

## Grouped bar totals (`graph.bar` 1.1)

Bar charts can now group events by category instead of drawing one row per event:

```json
{"kind": "graph.bar", "subscription": "alert_events", "categoryField": "zone",
 "valueField": "count", "aggregation": "sum",
 "requires": {"graph.bar": "1.1"}}
```

- `"sum"`: each bar is the total of `valueField` for that category.
- `"count"`: each bar is the number of events in that category.
- Without `aggregation`, charts behave as before (one row per recent event, up to 20).

To adopt it, add `aggregation` **and** `"requires": {"graph.bar": "1.1"}` to the chart. Using `aggregation` without the `requires` entry fails validation when you publish. Charts without `aggregation` need no change.

## Subscription time windows (`subscription.window` 1.0)

A subscription can now keep only recent events — useful for a "last hour" chart next to a full-history one over the same stream:

```json
{"id": "alert_events_1h", "source": "alerts", "mode": "events", "window": "1h"}
```

Available windows: `"1h"`, `"24h"`, `"7d"`. Each chart reading a windowed subscription declares `"requires": {"subscription.window": "1.0"}` on its own metric; without it, publishing fails.

Limits: a window filters what is already loaded on the device (about the latest 100–200 events), it does not reach further into history. On a busy product the window may hold fewer events than the time range suggests; on a quiet one, old events are correctly excluded.

## Older clients

Both features are opt-in and version-gated: charts using them are hidden (or fall back) on clients that do not support the version, never rendered incorrectly. Existing definitions are unaffected.
